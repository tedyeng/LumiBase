# Inspection 1.5.3 ready-frame ownership

## Cause

The first-frame reader and bitmap producers owned different caches. `PreviewPreloader` retained decoded previews in its actor, while Loupe's synchronous selection handoff only checked `ThumbnailCacheManager`. The selected photo was cleared before an asynchronous task waited for preload coordination, so a warm preview could not bridge the black interval. Native ROI results had the same timing gap: their actor cache was queried only after selection work started. The `liveDevelopAssetID == selectedID` gate also treated committed values and in-flight edits as the same state. An edited RAW could fall through to its embedded, unedited JPEG when thumbnail processing failed.

## Ownership and identity

`InspectionReadyFrameStore` is now the sole retained bitmap store for preloaded previews, completed Fit renders, and completed processed ROIs. It holds immutable `CGImage` values behind one lock and applies a combined 128 MiB LRU budget. The preview producer no longer retains a second copy in an actor-local cache, and the ROI service publishes into the same store. Memory pressure clears the consumer-visible store; producer cancellation and generation checks reject late results. Preview and ROI clear operations remain namespace-specific for ordinary teardown.

The synchronous Loupe body uses selected-asset ownership separately from settings freshness. A valid displayed frame remains visible during same-photo edits while the exact-settings render is pending, with `Updating settings · showing last valid frame`; the old revision is never tagged as current. A different photo still gets no prior owner's frame. Cached handoff remains strict: only exact settings, source version, camera, geometry, and source orientation can match. At 100%, a current preview can be shown while native work is pending. A cold lookup stays empty/loading. No disk read, file stat, or RAW decode is used in the body. Parsed `PhotoAsset` values carry the source orientation read during metadata scanning; quick-scan assets without verified orientation cannot match an ROI. `NSImage` wrappers are created at the main-actor display boundary; cached pixels cross actors and locks as immutable `CGImage` values.

Edited RAW speculation remains disabled. An edited RAW thumbnail failure now returns unavailable instead of presenting the embedded unedited preview. A full Fit frame becomes reusable only after the current processed render completes. Native ROI speculation remains a single background worker and shares the byte budget with previews.

## Limits

The 128 MiB value accounts retained ready-frame pixel bytes, not transient renderer allocations or process RSS. Native cache matching uses scanner `fileSize`/`dateModified` source version and parsed source orientation; external file changes become visible after the scanner refreshes that asset. The tests verify producer-to-consumer ownership and selection behavior, not a GUI session. No GUI or user photos were opened, so there is no measured first-frame latency or claim that a reported screen is fixed on a real library. A real GUI reproduction remains unverified.
